# Lark 多维表格配置指南（教师版）

做完这份文档，你会得到四样东西：

```
LARK_APP_ID       应用凭证
LARK_APP_SECRET   应用密钥（不要发给任何人）
app_token         多维表格 Base 的标识
table_id × 3      三张数据表各自的标识
```

> 界面文案可能随版本略有出入，按含义找入口即可。
> 若改用飞书，全部步骤相同，只是把 `larksuite.com` 换成 `feishu.cn`，
> 并把 `data/config.yaml` 里的 `base_url` 改成 `https://open.feishu.cn`。
> **两者是独立租户，数据不互通，必须二选一。**

---

## 阶段 A：创建应用

1. 打开 **<https://open.larksuite.com>**，登录开发者后台
2. **创建应用** → 选 **自建应用**（不是商店应用）
3. 名称填 `Kindle Dashboard`
4. 进入 **凭证与基础信息**，记下 **App ID**（形如 `cli_a1b2c3…`）和 **App Secret**

> App Secret 等同密码。**不要发在聊天里，也不要提交进仓库** ——
> 它只会存在你本机的环境变量和 GitHub Secrets 里。

---

## 阶段 B：开通权限并发布

1. **权限管理** → 搜 `bitable` → 勾选 **`bitable:app`**（查看、评论、编辑和管理多维表格）
2. **版本管理与发布** → 创建版本 → 申请发布 → 去管理后台自己批准

> **权限必须发布后才生效。** 只勾选不发布的话 API 会一直报权限错误，
> 而权限页面看起来一切正常 —— 这是最常见的卡点。

---

## 阶段 C：建多维表格

新建一个多维表格（Base），命名 `Kindle Dashboard 数据`，建三张数据表。

### 表 1：`课程表`（网格形态）

**表格做成和屏幕一模一样**：一行一个节次，一列一个星期，格子里填班级。
改课就是找到那一格改内容，不用在十几条散记录里翻找。

| 列名 | 类型 |
|---|---|
| 节次 | 文本（**第一列**）|
| 周一 | 文本 |
| 周二 | 文本 |
| 周三 | 文本 |
| 周四 | 文本 |
| 周五 | 文本 |

按课表原件填成这样，**空格子就是没课**：

| 节次 | 周一 | 周二 | 周三 | 周四 | 周五 |
|---|---|---|---|---|---|
| 1 |  |  |  |  |  |
| 2 |  | 一3班 | 二6班 |  | 二2班 |
| 3 |  |  |  |  | 二8班 |
| 4 | 四6班 | 二2班 | 一2班 |  |  |
| 5 | 二8班 | 一1班 | 一3班 | 一1班 | 一2班 |
| 6 |  |  |  | 四6班 | 二6班 |
| 7 |  |  |  |  |  |
| 8 |  |  |  |  |  |

第 7、8 节是课后服务时段，有安排时填，没有就空着。

节次对应的时间（第1节几点开始）不在这张表里 —— 那是全局作息，
定义在 `data/config.yaml` 的 `schedule.periods` 中，不该在每行重复。

### 表 2：`临时调整`

只影响指定某一天，不动上面的常规课表。**过期的行会被自动删除**，
你添加之后不需要回头打扫。

| 列名 | 类型 | 说明 |
|---|---|---|
| 日期 | 日期 | **必须是第一列** |
| 节次 | 文本 | 第几节 |
| 操作 | 单选 | 选项：停课 加课 换班 |
| 班级 | 文本 | 加课/换班时填；停课可留空 |
| 备注 | 文本 | 可空，写给自己看的原因 |

只需四个字段 —— **星期由日期推出来，原本是哪个班由网格查出来**，都不用重复填。

| 场景 | 怎么填 |
|---|---|
| 今天第5节不用上了 | 日期=今天，节次=5，操作=停课 |
| 周三第3节临时加一节给三2班 | 日期，节次=3，操作=加课，班级=三2班 |
| 明天第4节和别人换成了一1班 | 日期，节次=4，操作=换班，班级=一1班 |

**自动清理**：渲染时会删掉日期早于「今天减 3 天」的行。留 3 天缓冲是为了
避开时区边界，也方便你回头看最近改过什么。想调整或关闭，改
`config.yaml` 里的 `lark.overrides_cleanup_days`。

### 表 3：`待办`

| 列名 | 类型 | 说明 |
|---|---|---|
| 事项 | 文本 | **必须是第一列** |
| 完成 | 复选框 | **勾上就从 Kindle 屏幕消失** |
| 截止 | 日期 | 可空，显示为「今天/明天/3天/已逾期」 |
| 优先 | 复选框 | 勾上排最前并加粗 |
| 标签 | 文本 | 可空，空格分隔 |

---

## 阶段 D：把应用加进这个表格

**光有权限还不够，还要把 Base 授权给你的应用。**

1. 打开多维表格 → 右上角 **⋯ 更多** → **添加文档应用**
2. 搜到 `Kindle Dashboard`，添加，权限选 **可编辑**

> 漏掉这步会报「无权限访问该文档」，而权限页面看着完全正常。
> 自检工具会专门识别这个错误并提示。

---

## 阶段 E：抄下 ID 并自检

链接结构：

```
https://xxxxx.sg.larksuite.com/base/BASCNxxxxxxxx?table=tblYYYYYYYY&view=vewZZZZ
                                    └── app_token ──┘      └ table_id ┘
```

- **app_token**：三张表共用同一个
- **table_id**：**每张表都不同**，依次点开三个标签页各抄一次

填进 `data/config.yaml`：

```yaml
lark:
  app_token: "BASCN..."
  tables:
    schedule: "tbl..."
    overrides: "tbl..."
    todo: "tbl..."
```

然后跑自检：

```powershell
$env:LARK_APP_ID='cli_xxxxx'
$env:LARK_APP_SECRET='xxxxx'
python render/lark_check.py
```

自检会逐项验证：凭据 → token → app_token → 三张表的可读性和**列名匹配**。
列名对不上是最隐蔽的故障 —— 渲染器只会安静地跳过读不懂的行，
屏幕上表现为「数据莫名其妙少了几条」，不会有任何报错。

全部通过后，把 `config.yaml` 的 `data_source.provider` 改成 `lark`，
再跑一次渲染就能看到真实数据了。
